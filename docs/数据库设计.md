# 云枢 OA · 数据库设计

19 张业务表，MySQL 8 / H2 通用。建表脚本：`sql/schema-mysql.sql`（生产）、
`oa-server/src/main/resources/db/schema.sql`（开发自动执行）。

sys_user.id ──< sys_user_role.user_id >── sys_role.id ──< sys_role_menu.role_id >── sys_menu.id

wf_process_def.proc_key ──< wf_instance.proc_key

## 关键设计说明

### 1. 工作流用「定义 + 实例 + 任务」三张表

`wf_process_def.nodes_json` 示例：

```json
[
  {"key":"leader","name":"部门负责人审批","assignee":"leader"},
  {"key":"finance","name":"财务复核","assignee":"finance"},
  {"key":"gm","name":"总经理终审","assignee":"gm"}
]
```

- 发起单据 → 按定义取**第一个节点**创建 `wf_instance` 和一条 PENDING `wf_task`
- 审批通过 → 标记当前任务 DONE，取下一个节点创建新任务；已是最后节点则实例置 `APPROVED`
- 驳回 → 实例置 `REJECTED`，剩余 PENDING 任务批量置 `CANCELED`
- 撤回 → 实例置 `WITHDRAWN`
- 办理人由 `OrgService.resolveAssignee()` 按角色解析：`leader` 取申请人部门负责人，
  `hr/finance/gm` 取对应岗位人员，避免把用户 ID 硬编码进节点

表单以 `form_json` 快照保存，后续修改表单字段不影响历史单据，详情接口再用
`JsonCodec.parse()` 还原成对象给前端渲染。

### 2. RBAC 三层

- **菜单层**：`sys_role_menu` 决定侧边栏可见项，登录时 `listMenus` 下发
- **接口层**：`@RequirePerm("approval:audit")` + `JwtInterceptor` 查 `listPermCodes` 校验，
  前端隐藏按钮也绕不过后端
- **数据层**：`sys_role.data_scope` 预留 ALL / DEPT / SELF 三种范围

### 3. 会议室冲突检测

```sql
SELECT COUNT(*) FROM cal_event
WHERE room_id = #{roomId}
  AND start_time < #{end} AND end_time > #{start}
```

时间用 `yyyy-MM-dd HH:mm` 定长字符串存储，字典序即时间序，MySQL / H2 均可直接比较，
无需处理时区函数差异。

### 4. 分页

统一 `PageResult{total, rows, page, size}`，Mapper 用
`LIMIT #{size} OFFSET #{offset}`（H2 MySQL 模式与 MySQL 8 均支持），
Service 层做 page/size 边界收敛（size 上限 100）。

### 5. 索引

`att_checkin(user_id, check_date)`、`wf_instance(applicant_id)`、
`wf_task(assignee_id, status)`、`prj_task(project_id, status)` ——
对应打卡记录、我的申请、待我审批、看板四个最高频查询。

### 6. 审计日志无侵入

`AuditAspect` 切点匹配所有 Controller 的 `@PostMapping/@PutMapping/@DeleteMapping`，
在 finally 里取 `UserContext` 中的登录人、请求 URI、IP、耗时统一落库，
业务代码不需要写一行日志代码。
