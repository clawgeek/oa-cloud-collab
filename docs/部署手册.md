# 云枢 OA · 部署手册

> 三种部署方式，按环境任选其一。所有命令均为项目根目录 `oa-cloud-collab/` 下执行。

## 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17+ | SpringBoot 3.2.5 要求 |
| Maven | 3.9+ | 已内置 Wrapper，可不预装 |
| Node.js | 18+ | 推荐 20 LTS |
| MySQL | 8.0 | **仅生产环境需要**，开发环境用 H2 内存库 |
| Docker | 20+ | 方式一需要 |

---

## 方式零：本地开发（最快，零外部依赖）

后端 `dev` profile 使用 H2 内存数据库，启动时自动执行 `db/schema.sql` 与 `db/data.sql`，
**无需安装 MySQL、无需 Redis、无需配置任何账号密码**。

```bash
# 终端 1 · 后端 :8080
cd oa-server
./mvnw -DskipTests clean package
java -jar target/oa-server-1.0.0.jar
# 或用 Spring Boot 插件直接跑：./mvnw spring-boot:run

# 终端 2 · 前端 :5173
cd oa-web
npm install
npm run dev
```

验证：

```bash
curl http://localhost:8080/api/health
# {"code":200,"data":{"status":"UP","app":"yunshu-oa-server",...}}

curl -X POST http://localhost:8080/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username":"admin","password":"123456"}'
```

浏览器打开 http://localhost:5173 。Vite 通过 `vite.config.js` 把 `/api` 代理到 `:8080`，
因此不存在跨域问题。

## 方式一：Docker Compose 一键部署（推荐用于验收 / 演示）

```bash
# 可选：设置数据库口令与 JWT 密钥
export MYSQL_ROOT_PASSWORD='your-strong-password'
export OA_JWT_SECRET='a-long-random-secret'

docker compose up -d --build
docker compose ps
docker compose logs -f oa-server
```

启动顺序由 `depends_on: service_healthy` 保证：MySQL 通过健康检查后才启动后端。
MySQL 容器首次启动会自动执行 `sql/schema-mysql.sql` 与 `sql/data.sql` 完成初始化。

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 前端 | http://localhost | Nginx 托管 `dist/`，`/api` 反代后端 |
| 后端 | http://localhost:8080 | 直接访问也可（已开启 CORS） |
| MySQL | localhost:3306 | 数据卷 `oa_mysql_data` 持久化 |
| 上传文件 | 数据卷 `oa_uploads` | 持久化用户上传的文档 |

停止与清理：

```bash
docker compose down           # 保留数据卷
docker compose down -v        # 连数据卷一起删除（会清空演示数据）
```

## 方式二：手动部署（物理机 / 虚拟机）

### 1. 初始化 MySQL

```bash
mysql -uroot -p -e "CREATE DATABASE yunshu_oa DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -uroot -p yunshu_oa < sql/schema-mysql.sql
mysql -uroot -p yunshu_oa < sql/data.sql
```

`sql/data.sql` 中 12 个演示账号口令为 PBKDF2 散列值（明文 `123456`）。
**正式上线前请删除演示账号或全量修改口令。**

### 2. 打包并启动后端

```bash
cd oa-server
./mvnw -DskipTests clean package

SPRING_PROFILES_ACTIVE=prod \
MYSQL_HOST=127.0.0.1 MYSQL_PORT=3306 MYSQL_DB=yunshu_oa \
MYSQL_USER=root MYSQL_PASSWORD='your-password' \
OA_JWT_SECRET='a-long-random-secret' \
java -jar target/oa-server-1.0.0.jar
```

`prod` profile 关闭了 `spring.sql.init`（不会重复灌数据），数据源改为 MySQL 8 + HikariCP 连接池。

### 3. 打包前端

```bash
cd oa-web
npm ci
npm run build          # 产物 oa-web/dist/
```

把 `dist/` 拷到 Nginx 的 `html/` 目录，使用仓库内 `oa-web/nginx.conf` 作为站点配置，
`proxy_pass` 指向后端地址。若后端不在同一台机器，把 `http://oa-server:8080` 改成实际地址。

### 4. 反向代理要点

- 前端用 Vue Router **history 模式**，Nginx 必须配置 `try_files $uri $uri/ /index.html;`，否则刷新子路由 404
- 附件上传限制：`client_max_body_size 60m`（后端 `max-file-size: 50MB`）
- 生产环境建议给 `/api` 配 HTTPS，并把 `OA_JWT_SECRET` 放进环境变量 / 密钥管理服务

## 方式三：前后端分离独立部署

```
用户 → CDN / 对象存储（oa-web/dist 静态资源）
     → API 网关（/api 路由，可挂多实例 + 负载均衡）
         ├─ oa-server 实例 1 :8080
         ├─ oa-server 实例 2 :8081
         └─ ...（无状态，JWT 天然支持水平扩展）
     → MySQL 8 主从 / 云 RDS
     → 对象存储（替换 DocService 的本地落盘实现）
```

后端完全无状态（不依赖 Session），横向扩展只需保持 `OA_JWT_SECRET` 一致。
文件上传目录如需多实例共享，把 `DocService` 中 `Files.write` 替换为 MinIO / OSS SDK 即可，
数据库 `doc_file.storage_path` 字段无需改动。

## 配置速查

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | `dev` | `dev`=H2，`prod`=MySQL |
| `SERVER_PORT` | `8080` | 后端端口 |
| `MYSQL_HOST/PORT/DB/USER/PASSWORD` | 见 `application-prod.yml` | 仅 prod 生效 |
| `OA_JWT_SECRET` | 内置演示值 | **生产必须修改** |
| `OA_JWT_EXPIRE_HOURS` / `oa.jwt.expire-hours` | `12` | Token 有效期 |
| `OA_UPLOAD_DIR` | `./data/uploads` | 附件落盘目录 |

## 常见问题

**Q：启动报 `Port 8080 was already in use`**
改端口：`java -jar app.jar --server.port=8081`，前端代理目标同步修改。

**Q：登录返回「账号或密码错误」**
确认用的是 `dev` profile 且 H2 初始化成功（启动日志出现 `Tomcat started`），或 prod 下已导入 `sql/data.sql`。

**Q：前端刷新子页面 404**
Nginx 缺 `try_files ... /index.html`，见 `oa-web/nginx.conf`。

**Q：上传后下载 404**
检查 `OA_UPLOAD_DIR` 目录权限；多实例部署需共享存储卷或改对象存储。

**Q：国内网络 Maven 依赖慢**
`./mvnw -s .mvn/settings.xml clean package` 使用阿里云镜像。
